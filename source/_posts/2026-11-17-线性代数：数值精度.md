## 前言

把模型精度从 FP32 一路压到 FP8 甚至 FP4，能换来成倍的 Tensor Core 吞吐和显存带宽减负，但代价是每一步算术都在丢信息。一次低精度矩阵乘法 $\hat A \hat B$ 的误差包括两个部分：一个是输入量化成 $\hat A, \hat B$ 时的表示误差；第二个则是随着成千上万次乘加舍入，逐步滚大的累积误差。

## 浮点模型（Floating-Point Model）

在标准二进制浮点表示中，正规数写作 $x = \pm (1.f)_2 \times 2^{e - \text{bias}}$。当基本运算 $\circ \in \{+, -, \times, /\}$ 采用就近舍入且结果未溢出时，硬件给出的结果满足：

$$\operatorname{fl}(a \circ b) = (a \circ b)(1 + \delta), \qquad \lvert \delta \rvert \le u$$

这里的单位舍入误差 $u = 2^{-(t+1)}$ 完全由尾数(Mantissa)位数 $t$（不含隐含的 1）决定。一般的直觉是指数位管数值能跑多远（动态范围），尾数位管刻度能切多细（相对精度）。

|   格式   | 指数位E | 尾数位M |    $u$    |     最大值（约）     |
| :------: | :----: | :----: | :-------: | :------------------: |
|   FP32   |   8    |   23   | $2^{-24}$ | $3.4 \times 10^{38}$ |
|   TF32   |   8    |   10   | $2^{-11}$ | $3.4 \times 10^{38}$ |
|   BF16   |   8    |   7    | $2^{-8}$  | $3.4 \times 10^{38}$ |
|   FP16   |   5    |   10   | $2^{-11}$ |       $65504$        |
| FP8 E4M3 |   4    |   3    | $2^{-4}$  |        $448$         |
| FP8 E5M2 |   5    |   2    | $2^{-3}$  |       $57344$        |
| FP4 E2M1 |   2    |   1    | $2^{-2}$  |         $6$          |

从表里能直观看到设计取舍：BF16 保留了和 FP32 一样的 8 位指数，训练时不容易溢出，代价是尾数砍到只剩 7 位；到了 FP4 E2M1，单个未缩放元素最大只能表示 $6$，相邻刻度的相对误差高达 $25\%$，离开外部缩放机制根本没法直接用。

## 输入量化（Input Quantization）

低精度量化的头号天敌是 Transformer 激活值里常见的通道离群值（outliers）——少数几个极大值会强行撑大缩放因子，把同一组里的正常小值全部挤扁成零。现代低精度格式的技术演进，本质上就是围绕“缩小缩放粒度”和“提前打散尖峰”展开的：

- **缩小缩放粒度（Block Scaling）**：既然整张量共用一个缩放因子（per-tensor）会被离群值一锅端，那就把张量切块各自缩放，把离群值的破坏力关进局部笼子里。DeepSeek-V3 在 FP8 训练中采用 **1×128 激活分块 + 128×128 权重分块缩放**；OCP 微缩放规范（MXFP8 / MXFP4）则进一步切细到每 32 个元素共享一个 E8M0（2 的整数次幂）缩放因子。
- **双级精细缩放（NVFP4）**：到了 Blackwell 的 4-bit 时代，每元素只剩 E2M1 编码，32 元素的块依然嫌大。NVFP4 把一维块缩到 16 个元素，并将块级缩放因子升级为精度更高的 FP8 E4M3（允许取非 2 的幂次），外加一个张量级的 FP32 全局缩放因子：

  $$\hat{x}_i = q_i \times s_{\mathrm{block}(i)} \times s_{\mathrm{global}}$$

  算下来每元素均摊 $4 + 8/16 = 4.5$ 位（另计全局因子与对齐开销）。即便如此，如果某个 16 元素块里恰好撞上极端离群值，同块里的小值依然难逃被舍入成零的命运。

- **量化前正交旋转（Hadamard 旋转）**：既然缩放粒度已经压到极限，那就从源头消除尖峰。以 QuaRot 为代表的方法在量化前插入一对正交矩阵 $H$（满足 $H H^\top = I$），把恒等变换改写为 $XW = (XH)(H^\top W)$。正交旋转不改变内积结果，却能把集中在少数通道上的能量均匀摊平到所有坐标上，大幅减轻离群值对低比特量化的冲击。

## 点积中的舍入误差

就算输入已经完美量化，大模型的隐藏层维度动辄几千上万，把这么长的乘积序列累加起来本身就是一场误差累积战：

- **顺序累加的线性漂移**：严格按从左到右顺序累加 $n$ 项内积时，最坏情况下的舍入误差界随维度 $n$ 近似线性增长：

  $$\lvert \operatorname{fl}(x^\top y) - x^\top y \rvert \le \gamma_n\, \lvert x \rvert^\top \lvert y \rvert, \qquad \gamma_n = \frac{nu}{1 - nu} \quad (nu < 1)$$

- **大数吃小数（Swamping）**：这是顺序累加在低精度下最致命的故障模式。在 $a + b$ 中，一旦累加和 $a$ 滚雪球变得足够大，而新进来的乘积 $\lvert b \rvert$ 小于 $a$ 附近相邻浮点数间距的一半，硬件加法器算出的结果就原封不动等于 $a$——后面所有的有效小信号全被无声吞没。
- **算法层面的止损**：**两两配对求和（Pairwise Summation）**把串联加法改成二叉树归约，误差系数从 $\gamma_n$ 骤降至 $\gamma_{\lceil \log_2 n \rceil}$；**Kahan 补偿求和**则额外维护一个低位补偿变量，把每次舍入丢掉的尾巴攒起来补进下一轮。
- **硬件层面的两级累加**：GPU Tensor Core 内部为了省面积，低精度乘加器往往不会全程用全精度。DeepSeek-V3 在 Hopper 上做 FP8 矩阵乘时，每累加一定步长就把 Tensor Core 里的部分和搬到 CUDA Core 用 FP32 汇总，阻断低精度累加器的精度退化（当然，输入量化阶段已经丢掉的信息不可能靠这一步变回来）。

## 条件数与稳定性

把上面所有的量化噪点和舍入误差打包起来，从数值线性代数的视角看，等效于我们在精确问题上施加了一个微小的相对扰动 $\lVert \Delta A \rVert / \lVert A \rVert = O(u)$——即所谓**后向稳定性（Backward Stability）**：算出的 $\hat{x}$ 其实是某个邻近问题 $(A + \Delta A)\hat{x} = b$ 的精确解。

但这并不保证最终结果 $\hat{x}$ 离真解 $x$ 很近，中间还隔着**条件数（Condition Number）**这根放大杠杆：

$$\kappa(A) = \lVert A \rVert_2 \lVert A^{-1} \rVert_2 = \frac{\sigma_{\max}}{\sigma_{\min}}, \qquad \frac{\lVert \hat{x} - x \rVert}{\lVert x \rVert} \lesssim \kappa(A) \cdot \frac{\lVert \Delta A \rVert}{\lVert A \rVert}$$

当矩阵奇异值跨度极大（病态，ill-conditioned）时，哪怕输入端只有微不足道的舍入扰动，输出误差也会被 $\kappa(A)$ 成倍放大。例如取 $A = \operatorname{diag}(1, 10^{-4})$、$b = (1, 0)^\top$，只需在 $b$ 的第二项加上一个 $10^{-4}$ 的微扰，解的第二项就会从 $0$ 剧烈跳变到 $1$。

还有一个常见的八股是**消去误差（Catastrophic Cancellation）**：两个几乎相等的浮点数相减，高位有效数字全部抵消，留下的全是低位舍入噪声。遇到类似 $\sqrt{x+1} - \sqrt{x}$ 的表达式，必须做代数改写（如 $1 / (\sqrt{x+1} + \sqrt{x})$）绕开直接相减。

## 小实验

**同一个点积，分别观察输入和累加误差。** 先用 FP16 舍入输入，在高精度下计算乘积；再对同一批乘积分别用 FP16 和 FP32 顺序累加，每步模拟硬件舍入。

```python
from math import fsum
from random import Random
from struct import pack, unpack

def rounded(x, fmt):
    return unpack(fmt, pack(fmt, x))[0]  # e: FP16, f: FP32

rng = Random(42)
pairs = [(rng.random(), rng.random()) for _ in range(16384)]
reference = fsum(a * b for a, b in pairs)
products = [rounded(a, "e") * rounded(b, "e") for a, b in pairs]
quantized = fsum(products)
print("input quantization:", abs(quantized - reference) / abs(reference))

for label, fmt in [("FP16", "e"), ("FP32", "f")]:
    total = 0.0
    for p in products:
        total = rounded(total + p, fmt)
    print(label, "accumulation:", abs(total - quantized) / abs(quantized))
```

跑下来会发现 FP16 顺序累加的相对误差接近 50%。如果部分和超过 $2048$，后面进来的小乘积在加法器里直接被吃光。

**同一输入，用 FP8 比较整张量缩放、分块缩放和 Hadamard 旋转。** 在 FP32 下测反量化后的相对误差。

```python
import torch
from scipy.linalg import hadamard

torch.manual_seed(42)
d = 128
x = torch.randn(1, d)
x[0, 0] = 50.0  # 制造典型 Transformer 通道离群值

def quant_fp8_sim(t):
    scale = t.abs().amax(dim=-1, keepdim=True) / 448.0
    return (t / scale).to(torch.float8_e4m3fn).float() * scale

H = torch.tensor(hadamard(d) / (d ** 0.5), dtype=torch.float32)
err_raw = (x - quant_fp8_sim(x)).norm() / x.norm()
err_block = (x - quant_fp8_sim(x.reshape(-1, 16)).reshape_as(x)).norm() / x.norm()
err_rot = (x - quant_fp8_sim(x @ H) @ H.T).norm() / x.norm()
print(f"Tensor: {err_raw:.4f} | Block: {err_block:.4f} | Rotated: {err_rot:.4f}")
```
