线性代数：分块矩阵乘法

发表于2026-11-17|更新于2026-11-18|数学
|浏览量:

前言

在理论和高层级api调用者眼里，矩阵乘法是一次性完成的一个整体映射；但在 GPU 底层和多卡集群里，完整的大矩阵很大可能是片上 SRAM 装不下，卡间互联又传不起。系统工程师眼里的矩阵乘法需要把大矩阵切碎、搬运、在局部算完后再拼回去。

分块矩阵乘法（Block Matrix Multiplication）

只要切分边界对齐（$A$ 的列切分与 $B$ 的行切分一致），把 $p \times q$ 块的 $A$ 与 $q \times r$ 块的 $B$ 相乘，做法和标量矩阵乘法完全一样，只是乘法不满足交换律，块间顺序不能乱调：

$$C_{ij} = \sum_{k=1}^{q} A_{ik} B_{kj}$$

最常用的三种切法：

  • 按列切 $B = [B_1, B_2]$：$AB = [AB_1,\ AB_2]$，输出天然按列劈成两半，互不干扰；
  • 按行切 $A = [A_1^\top, A_2^\top]^\top$：$AB = [(A_1 B)^\top,\ (A_2 B)^\top]^\top$，输出按行独立计算；
  • 沿内维切 $A = [A_1, A_2]$，$B = [B_1^\top, B_2^\top]^\top$：$AB = A_1 B_1 + A_2 B_2$，各自算出一半结果，最后做一次累加归约（Reduction）。

算术强度（Arithmetic Intensity）与分块（Tiling）

现代 GPU 的算力与显存带宽严重失衡：以 B200 为例，FP16 算力约 2200 TFLOPS，HBM 带宽却只有 8.19 TB/s，算力带宽比高达 ~280 FLOPs/Byte。根据 Roofline 模型 $P = \min(\pi,\ I\beta)$，如果算子不能在片上实现极高的数据复用，让算术强度 $I = \frac{\text{FLOPs}}{\text{Bytes}} \ge \frac{\pi}{\beta}$，计算单元就只能干等显存喂数据，死死卡在 Memory-bound 区域。

Tiling 正是撬动数据复用的杠杆。假设我们在片上算一块 $b_M \times b_N$ 的输出 tile，沿inner dim每次步进 $b_K$：每轮从显存搬入 $(b_M + b_N)b_K$ 个元素，就能在寄存器和 Tensor Core 里完成 $2 b_M b_N b_K$ 次浮点运算。以每元素 2 字节的 FP16 估算（仅计本轮输入读取）：

$$I \approx \frac{b_M b_N}{b_M + b_N}$$

tile 尺寸 $b$ 越大，算术强度就线性往上涨。但在真实的 SM 硬件上，tile 尺寸很快会撞上两堵物理墙：

  1. 寄存器与共享内存（Shared Memory）容量上限：tile 贪大，单个线程块吃掉的片上资源就会暴涨，导致每个 SM 能同时驻留的块数（occupancy）骤降，掩盖不了访存延迟；一旦超出寄存器上限触发寄存器溢出（register spilling），数据反而被踢回本地内存，得不偿失。
  2. 波次量化（Wave Quantization）：GPU 按“波(wave)/ 线程束 (Warp)”调度线程块，每波能同时跑多少块取决于 SM 总数与单 SM 驻留上限。如果切出来的总块数刚好比一整波多出几个，最后一波就只能让绝大多数 SM 闲置空转，白白拉低整体吞吐。

结合律与注意力

标准多头注意力面对序列长度 $N$ 和头维度 $d$ 时，面临一个经典的算力与显存困局。单看矩阵乘法的结合律，对 $Q, K, V \in \mathbb{R}^{N \times d}$ 改变加括号的顺序，计算复杂度截然不同：

$$(QK^\top)V : O(N^2 d), \qquad Q(K^\top V) : O(N d^2)$$

长上下文（$N \gg d$）下先算 $K^\top V$ 便宜得多，这也是线性注意力（Linear Attention）的立身之本。可惜标准注意力在 $QK^\top$ 之后横插了一道逐行 softmax，直接破坏了结合律，逼得朴素实现必须先把 $N \times N$ 的注意力矩阵完整物化到 HBM 里，引发灾难性的显存读写。

FlashAttention 的思路是“分块 + 在线修正（Online Softmax）”：既然不能换括号，那就把 $K, V$ 按行切块流式读入片上，边算边修正常数。举个极简例子：假设某一行先读到分数 $[0, 0]$，此时行最大值 $m=0$，分母 $\ell = e^0 + e^0 = 2$；下一块读到 $[2]$，行最大值刷新为 $2$。为了对齐基准，旧块对分母的贡献只需乘一个修正因子 $e^{0-2} = e^{-2}$ 变成 $2e^{-2}$，旧的加权输出同样乘 $e^{-2}$ 即可。

推广到任意分块 $S_j = QK_j^\top$，片上只需维护三个状态量——当前行最大值 $m$、归一化分母 $\ell$ 和未归一化输出 $O$：

$$m^{\text{new}} = \max\left(m^{\text{old}},\ \operatorname{rowmax}(S_j)\right)$$

$$\ell^{\text{new}} = e^{m^{\text{old}} - m^{\text{new}}}, \ell^{\text{old}} + \operatorname{rowsum}\left(e^{S_j - m^{\text{new}}}\right)$$

$$O^{\text{new}} = \operatorname{diag}\left(e^{m^{\text{old}} - m^{\text{new}}}\right) O^{\text{old}} + e^{S_j - m^{\text{new}}} V_j$$

所有块扫完后做一次 $\operatorname{diag}(\ell)^{-1} O$ 收尾，全程那个庞大的 $N \times N$ 矩阵从未在 HBM 里出现过。

这套状态机顺带盘活了训练反向与推理加速的两个关键优化：

  • 反向重计算（Recomputation）：既然前向省掉了 $N \times N$ 矩阵，反向传播时自然没法直接读取它。FlashAttention 只在前向存下轻量的 logsumexp 向量 $L = m + \log\ell$，反向时利用 $Q, K$ 和 $L$ 在片上当场重算概率矩阵——用廉价的算力换掉昂贵的 HBM 往返。
  • 推理期跳过低贡献块（BLASST）：TensorRT-LLM 的 Skip Softmax Attention 直接复用了 online softmax 的状态跟踪。算出当前块分数 $S_j = QK_j^\top$ 后，kernel 顺手对比块内行最大值与历史最大值 $m$：若当前块分数低得离谱，经过 $e^{S_j - m}$ 指数衰减后对输出几乎零贡献。此时 kernel 会跳过 softmax 更新、省掉从显存加载 $V_j$ 以及后续矩阵乘法的全部开销。注意 $QK_j^\top$ 仍需计算以充当“探针”，所以这是用可控的近似换取显存与算力节流，阈值调得越高跳得越狠，越需要盯紧精度验证（FlashInfer 部分 prefill 内核已支持该路径，详见 BLASST 论文、TensorRT-LLM 文档 与 FlashInfer API）。

张量并行（Tensor Parallelism, TP）

当单个算子大到单卡塞不下时，前面那三种分块刀法就直接变成了多卡间的通信拓扑。设权重为 $A$、输入为 $X$，切到两张卡上：

  • 列并行（Column Parallelism）：按列切权重 $A = [A_1, A_2]$，得到 $XA = [XA_1,\ XA_2]$。只要每张卡握有完整输入 $X$ 且下游允许输出保持分片，前向计算实现零通信。
  • 行并行（Row Parallelism）：按行切权重 $A = [A_1^\top, A_2^\top]^\top$，配合按列切分的输入 $X = [X_1, X_2]$，得到 $XA = X_1 A_1 + X_2 A_2$。各卡算完局部和后，需要一次 All-Reduce 才能拼出完整结果。

为什么 Transformer 的 MLP 总是“先列并行、后行并行”？ 看公式 $Y = \operatorname{GeLU}(XA),B$ 就明白：第一层 $A$ 用列并行，得到的分片 $[XA_1, XA_2]$ 各自独立过逐元素的 GeLU 激活，完全不需要跨卡通信；紧接着这些分片恰好无缝对接第二层 $B$ 的行并行输入，把通信压榨到整个 MLP 结束时的那一次 All-Reduce。如果再叠加上序列并行（Sequence Parallelism），还可以把这次 All-Reduce 拆成 Reduce-Scatter 和稍后的 All-Gather，让夹在中间的 LayerNorm 和 Dropout 也按 token 维度分摊，避免每张卡重复存储整份激活值。
